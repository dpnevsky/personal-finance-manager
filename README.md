# Personal Finance Manager

[![Java CI](https://github.com/dpnevsky/personal-finance-manager/actions/workflows/java-ci.yml/badge.svg)](https://github.com/dpnevsky/personal-finance-manager/actions/workflows/java-ci.yml)

Консольное приложение на Java 21 для учёта личных финансов. Учебный проект.

## Возможности

- Регистрация и вход нескольких пользователей с отдельными кошельками.
- Учёт доходов и расходов с категориями и историей операций.
- Лимиты расходов по категориям, предупреждения при достижении 80% и превышении лимита.
- Баланс, общие отчёты, суммы по выбранным категориям.
- Переводы средств между пользователями.
- Переименование и удаление неиспользуемых категорий; обновление и удаление бюджетов.
- Сохранение всех учётных записей и кошельков в локальном JSON; импорт и экспорт операций в CSV.
- Автоматическая проверка тестов и Checkstyle через GitHub Actions.

## Технологии

Java 21, Maven, JUnit 5, Jackson, Apache Commons CSV, Checkstyle и GitHub Actions. Для денежных сумм применяется `BigDecimal`, для паролей — хеширование PBKDF2-HMAC-SHA256 с солью.

## Сборка и запуск

Требуются **JDK 21** и **Maven**.

```bash
git clone https://github.com/dpnevsky/personal-finance-manager.git
cd personal-finance-manager
mvn clean verify
java -jar target/personal-finance-manager-1.0-SNAPSHOT.jar
```

Приложение интерактивное: сначала вводится команда, после чего — ответы на приглашения. Команда с параметрами не вводится в одну строку.

### Пример работы

Последовательно введи следующие строки, отвечая на приглашения программы:

```text
register
alice
password123
login
alice
password123
income
20000
Salary
expense
800
Food
budget
Food
4000
report
exit
```

Результат отчёта для примера:

```text
=== Financial Report ===
Total income: 20000
Total expenses: 800
Balance: 19200
=== INCOME Categories ===
Salary: 20000
=== EXPENSE Categories ===
Food: 800
=== Budgets ===
Food | Limit: 4000 | Spent: 800 | Remaining: 3200
```

При следующем запуске данные будут загружены из `data/users.json`.

## Команды CLI

| Команда | Назначение |
| --- | --- |
| `register` | Регистрация пользователя |
| `login` / `logout` | Вход и выход из учётной записи |
| `whoami` | Текущий пользователь |
| `income` / `expense` | Добавление дохода или расхода |
| `balance` | Баланс кошелька |
| `category` / `categories` | Создание и просмотр категорий |
| `budget` / `budgets` | Создание/обновление лимита и просмотр бюджетов |
| `report` | Общий отчёт о финансах |
| `total` | Сумма по выбранным категориям |
| `transactions` | История операций |
| `transfer` | Перевод другому пользователю по логину |
| `rename-category` | Переименование категории с обновлением истории |
| `delete-category` | Удаление категории без операций и бюджета |
| `delete-budget` | Удаление бюджета категории |
| `export-csv` | Экспорт транзакций текущего пользователя в CSV |
| `import-csv` | Импорт транзакций в текущий кошелёк из CSV |
| `help` | Справка |
| `exit` | Сохранение данных и завершение программы |

Пример для `total`: выбери `expense`, затем введи `Food, Taxi`. Для экспорта CSV можно указать `exports/alice.csv`. Суммы допускают десятичную точку или запятую: `1250.50` и `1250,50`.

### Правила операций

- Доходы и расходы автоматически создают отсутствующие категории; бюджет устанавливается для существующей категории расходов.
- При достижении 80% и превышении лимита появляются предупреждения. Обычные расходы могут привести к отрицательному балансу, о чём программа предупреждает.
- Перевод требует достаточного остатка и не допускает отправку самому себе. У отправителя записывается расход, у получателя — доход.
- Переименование категории сохраняет идентификаторы и даты прежних транзакций и переносит связанный бюджет; удалить категорию с операциями нельзя.
- Повторный импорт того же CSV не создаёт дубликатов по UUID; противоречащая существующей операция с тем же UUID отклоняется.
- Бюджет учитывает всю историю расходов по категории: автоматического ежемесячного сброса нет.

## Хранение данных

В процессе работы состояние хранится в памяти. При запуске читается `data/users.json`, при штатном завершении (команда `exit` или закрытие потока ввода) состояние сохраняется в JSON. В файл входят логины, **хеши**, а не открытые пароли, категории, лимиты и операции с UUID, датами и суммами. Для сохранения JSON используется временный файл и замена основного.

CSV содержит **только операции**, но не учётные записи, пароли и бюджеты. Импорт применяется к текущему авторизованному пользователю. Рабочие каталоги `data/`, `exports/`, `target/` исключены из Git.

## Архитектура

| Пакет | Ответственность |
| --- | --- |
| `model` | Модели пользователя, кошелька, операции, категории, бюджета и результатов |
| `repository` | Интерфейс `UserRepository` и реализация `InMemoryUserRepository` |
| `security` | `PasswordHasher` |
| `service` | Авторизация, финансовые операции, бюджеты, переводы, CSV |
| `storage` | `JsonFileStorage` и `CsvTransactionStorage` |
| `cli` | Консольные команды и форматирование таблиц |
| `Main` | Создание объектов, загрузка, запуск, сохранение |

В проекте используются инкапсуляция, неизменяемые значения транзакций, интерфейсы и конструкторное внедрение зависимостей, отделение бизнес-логики от файлового хранения и UI.

## Проверка качества

```bash
mvn test
mvn clean verify
```

На момент подготовки README — **142 теста**, включая модульные тесты моделей и сервисов, сохранение в JSON, работу с CSV и интеграционные сценарии CLI. `mvn clean verify` также запускает Checkstyle и создаёт исполняемый JAR.

GitHub Actions автоматически проверяет каждый push и pull request в ветку `main`: [Java CI](https://github.com/dpnevsky/personal-finance-manager/actions).

## Ограничения и безопасность

Это **учебное локальное CLI-приложение**, не банковская платформа. В терминале ввод пароля не скрыт, хотя на диск сохраняется только хеш с солью. Для демонстрации используй отдельные тестовые логины и пароли. JSON-файл с данными не следует публиковать.

Сохранение происходит при штатном завершении работы, а не после каждой операции. Перевод записывается в двух кошельках последовательно и не имеет полноценной транзакционной гарантии при исключении или аварийном завершении процесса. Конкурентные операции, шифрование файла данных и многопроцессная работа не реализованы.
